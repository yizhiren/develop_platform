# 里程碑 18：Agent4 独立验收工具循环

- 日期：2026-08-06
- 状态：已实现，完成自动化验证

## 问题

原 Agent4 能收到需求规格、架构方案、开发报告和干净 checkout 清单，但运行方式仍是单次结构化模型调用。平台只复跑开发工程师记录的测试；Agent4 自身不能检查仓库、选择新测试或执行验证。`AcceptanceReport` 也没有服务端逐项覆盖和证据真实性门禁，因此模型理论上可以遗漏验收项或在没有直接证据时批准。

## 实现

1. 新增只读 `AcceptanceToolLoop`，用于普通验收、逐仓组合回归和最终验收。
2. Agent4 从确认后的 `acceptance_criteria` 获取“测哪些”，从 `verification_method`、架构测试策略和仓库内容决定“怎么测”。
3. 工具面只包含列目录、读取初始干净文件、运行白名单验证命令和结束；每个检查动作必须标记直接覆盖的验收项。
4. 平台为文件检查和独立命令生成稳定证据 ID，模型不能自行声称某个路径就是证据。
5. 批准要求至少一个 Agent4 独立成功命令；每个通过项都必须绑定本项的成功证据，全部确认验收项必须完整且不重复出现。
6. 工具循环在命令前对初始文件做 SHA-256 快照；修改、删除初始文件或创建非测试产物会产生完整性失败证据。
7. Control Plane 在结果落库和状态转换前再次执行覆盖、证据、必选项和独立命令门禁，防止不完整批准推进工作流。
8. 旧的无仓库 Fake 协议模式保持兼容；开启仓库自动化后缺少对应干净验证工作区会明确失败，不再降级为文本验收。

## 验证

- Agent4 能读取两条确认验收标准，检查文件、独立运行 pytest，并为每条标准返回直接证据。
- 不完整报告第一次 `finish` 被拒绝，补齐遗漏验收项和证据后才能通过。
- 验证命令修改初始源码时，即使退出码为 0 也只能形成失败报告。
- Control Plane 拒绝伪造证据、遗漏验收项或没有 Agent4 独立成功命令的批准。
- Fake Provider 能完成相同的多步验收工具协议，普通测试不调用付费模型。
- 新增显式 `RUN_LIVE_AI_TESTS=1` 的 DeepSeek Agent4 工具循环用例；默认验证不调用付费模型。
- 后端 103 项非实时测试全部通过，`git diff --check` 通过。
