# 里程碑 8：方案评审与开工授权

- 日期：2026-08-06
- 状态：本地完成

## 问题

需求进入 `AWAITING_PLAN` 后，页面先显示通用 `HUMAN GATE` 和批准/退回按钮，完整方案却被埋在页面下方的通用产物区域。负责人无法在当前决策位置看到修改范围、测试、风险和回滚信息。同时，“要求调整方案”的文字只进入审批记录，没有进入下一轮系统架构师的任务上下文。

## 实现决策

- 在批准按钮前结构化展示当前状态、目标架构、执行步骤和逐仓改动。
- 单独展示接口影响、数据库变更、安全考虑、测试策略、回滚方案和主要风险。
- “批准方案并开始开发”明确表示授权产生代码变更。
- “要求系统架构师调整”必须填写具体意见；空意见在前后端同时拒绝。
- 退回意见持久化到 `conversation_messages`，并随旧版 `architecture_plan` 进入下一轮系统架构师上下文。
- 仅记录的讨论消息仍可审计，并在后续重新设计时进入上下文。

## 验证计划

| 验证 | 预期结果 |
| --- | --- |
| 方案反馈工作流单测 | 调整意见持久化并进入下一轮 `agent.architect` 上下文 |
| 空意见校验 | 无具体意见时不能退回方案 |
| 前端检查与构建 | 结构化方案区、按钮状态和响应式布局通过 |
| 本地容器 | Control Plane 健康，Web 页面正常响应 |
