# ADR-0007：内置 SQLite 迁移与工作区租约

- 状态：接受
- 日期：2026-08-05

## 背景

平台选择 SQLite 是为了低运维，但 `create_all` 只能创建缺失表，不能可靠升级长期运行的数据文件。代码工作区又会随需求数增长，需要明确容量和回收规则。

## 决策

- 使用仓库内置、严格递增的 Python 迁移清单和 `schema_migrations` 表；控制平面启动时在事务中依次执行。
- 未知迁移版本立即拒绝启动，避免新代码误读由更高版本创建的数据库。
- 初始迁移对已有 `create_all` 数据库兼容；后续迁移必须在旧库与新库上幂等。
- 每个开发/验证工作区使用需求级目录；租约时间保存在工作区根目录之外的 `.leases`，Agent 无法修改。
- prepare 前清理超过 TTL 的目录，clone 完成后检查总字节配额。超额时删除本次工作区并失败，不留下半成品。
- 提供 `workspace-cleanup` Compose tools profile，便于定时任务独立执行。

## 后果

无需运行独立数据库迁移服务，也不引入 PostgreSQL 运维成本。缺点是迁移能力比 Alembic 简单，复杂表重建必须手写并充分备份验证；工作区清理依赖外部定时调度或后续 prepare 触发。
